Export IFC depuis Revit : 6 bonnes pratiques

2026-10-10 · 4 min de lecture

Vos chemins de câbles apparaissent-ils dans la maquette fédérée ? Si l'export IFC n'est pas réglé, ils arrivent chez le coordinateur sous forme d'objets anonymes, impossibles à filtrer. L'IFC permet à des logiciels différents de partager une même maquette. Encore faut-il le configurer.

L'IFC est un format d'échange, pas un format de travail

L'IFC (Industry Foundation Classes) est un format ouvert, normalisé ISO 16739 et porté par buildingSMART. Il transporte la géométrie, les propriétés des objets et leurs relations, sans dépendre d'un éditeur. C'est la base de l'openBIM.

Il n'est pas paramétrique pour autant. La logique famille, type et instance de Revit disparaît à l'export : chaque élément devient une géométrie figée avec ses propriétés. Chacun continue donc à travailler dans son format natif, et l'IFC ne sert qu'à échanger.

1. Utiliser l'exportateur IFC à jour

Autodesk a placé le moteur IFC de Revit en open source en 2011. Il évolue plus vite que Revit lui-même et offre une interface d'export bien plus complète que celle de base. Installez sa dernière version pour votre version de Revit : beaucoup de défauts d'export y sont déjà corrigés.

2. Créer une configuration d'export par projet

Ne partez pas des réglages par défaut. Dupliquez une configuration et enregistrez-y ce que prévoit la convention BIM :

  • la version IFC et la phase exportée (IFC2x3 ou IFC4, avec la bonne définition de vue) ;
  • la découpe des murs et poteaux par niveau, souvent attendue par les autres logiciels ;
  • les jeux de propriétés : propriétés Revit, jeux communs IFC, quantités de base ;
  • le stockage du GUID IFC dans Revit, pour que chaque objet garde le même identifiant d'un export à l'autre.

Partagez ensuite ce fichier avec toute l'équipe. Deux exports faits avec des réglages différents ne se comparent pas.

3. Soigner la table de correspondance des classes

C'est le réglage qui décide si vos objets sont lisibles chez les autres. Revit range les objets par catégories, l'IFC par classes, et la table fait le lien : les murs deviennent des IfcWall, les portes des IfcDoor. Sans correspondance, Revit exporte l'objet en IfcBuildingElementProxy, une classe fourre-tout.

Pour les lots électriques en IFC4, vérifiez au moins ces lignes :

Catégorie RevitClasse IFC4 attendue
Chemins de câblesIfcCableCarrierSegment
Raccords de chemins de câblesIfcCableCarrierFitting
ConduitsIfcCableCarrierSegment (conduit)
LuminairesIfcLightFixture
Équipements électriques (tableaux)IfcElectricDistributionBoard

Le piège classique : les modèles génériques. Sans réglage, ils finissent tous en proxy.

4. Forcer la classe dans la famille

Quand une famille ne rentre dans aucune catégorie Revit adaptée, deux paramètres partagés de type texte imposent sa classe : IfcExportAs pour la classe, IfcExportType pour le type prédéfini. Renseignés dans la famille, ils priment sur la table de correspondance. Une famille bien faite se pense donc dès sa création pour l'export, gabarit et paramètres compris.

5. Lier un IFC reçu, ne pas l'ouvrir

Ouvrir un IFC dans Revit crée un nouveau projet, coupé de sa source. À la prochaine mise à jour de l'émetteur, vous ne pourrez pas suivre. Un IFC lié se recharge à chaque version, accepte les accrochages et les cotations, et se pilote vue par vue comme n'importe quel lien Revit.

6. Contrôler l'IFC avant de l'envoyer

Un export n'est validé qu'une fois ouvert dans une visionneuse IFC indépendante. Vérifiez au minimum :

  • les classes : aucun objet métier en proxy ;
  • les propriétés : les paramètres demandés par la convention sont présents et renseignés ;
  • la position : la maquette se superpose aux autres lots, au bon point de référence ;
  • les couleurs : un objet gris dans Revit peut apparaître blanc dans la visionneuse, ce qui gêne la lecture en réunion.

Ce contrôle prend quelques minutes. Il évite de découvrir en réunion de synthèse que vos réseaux électriques sont introuvables dans la maquette fédérée.

Le réflexe à prendre

Si vous ne retenez qu'une pratique, gardez la dernière : ouvrez chaque IFC dans une visionneuse avant de l'envoyer. La configuration d'export et la table de correspondance se règlent une fois par projet. Le contrôle, lui, se fait à chaque diffusion.

Questions fréquentes

L'IFC (Industry Foundation Classes) est un format ouvert et normalisé (ISO 16739) qui décrit les objets d'une maquette BIM, leurs propriétés et leurs relations. Il permet d'échanger des maquettes entre logiciels d'éditeurs différents.

Il vaut mieux le lier. Un IFC lié peut être rechargé à chaque mise à jour de l'émetteur, alors qu'un IFC ouvert devient un projet indépendant, coupé de sa source.

Parce que leur catégorie Revit n'a pas de correspondance définie dans la table d'export, ce qui arrive souvent avec les modèles génériques. Il faut corriger la table ou renseigner les paramètres IfcExportAs et IfcExportType dans la famille.

Celle que fixe la convention BIM du projet. L'IFC4 décrit mieux les équipements techniques, mais tous les logiciels des intervenants doivent la prendre en charge correctement en import comme en export.
